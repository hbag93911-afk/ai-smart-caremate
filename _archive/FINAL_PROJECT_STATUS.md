## 🗄️ 데이터베이스 스키마 (최종)

### workout_records (기존 - 보존됨)
```sql
- id: 고유 ID
- date: 운동 날짜
- squat_count: 스쿼트 횟수
- duration: 운동 시간 (초)
- notes: 메모
```

### walk_records (기존 - 보존됨)
```sql
- id: 고유 ID
- date: 보행 날짜
- steps: 걸음 수
- duration: 보행 시간 (초)
- cadence: 분당 걸음 수 (케이던스)
- notes: 메모
```

### goals (신규 - 목표 관리)
```sql
- id: 고유 ID
- goal_type: 'squat' 또는 'walk'
- target_value: 목표값 (스쿼트 횟수 또는 걸음 수)
- created_date: 목표 생성 날짜
- updated_date: 마지막 수정 날짜
- is_active: 활성 여부 (1=활성, 0=비활성)
```

### daily_goals (신규 - 일일 달성 현황)
```sql
- id: 고유 ID
- goal_date: 달성 날짜
- goal_type: 'squat' 또는 'walk'
- target_value: 목표값
- achieved_value: 달성값
- achievement_rate: 달성률 (%)
```

## ⚠️ 제한사항 및 주의사항

### 1. 카메라 관련
- 웹캠이 필수적으로 연결되어야 함
- 카메라 권한 허용 필요
- 조명이 충분해야 관절 인식 정확도 높음
- 전신이 화면에 보여야 정확한 분석 가능

### 2. 목표 관리
- 목표는 세션 시작 시 DB에서 자동 로드
- 활동이 없는 날은 달성도 기록 없음
- 목표값은 정수값만 입력 가능

### 3. 데이터 분석
- 최소 7일 이상의 데이터가 있어야 주간 분석 의미 있음
- 최소 30일 이상의 데이터가 있어야 월간 분석 의미 있음
- 의료적 진단이 아닌 참고 정보일 뿐

### 4. 성능
- 초대형 데이터셋에서는 분석 속도 저하 가능
- 메모리 사용량: 약 500MB ~ 1GB

## 📞 문제 발생 시 대응

### 카메라가 작동하지 않을 때
1. 카메라 연결 확인
2. 카메라 권한 허용 확인
3. `camera.py` 작동 확인

### 관절이 인식되지 않을 때
1. 조명 확인 (너무 어둡지 않은지)
2. 거리 확인 (너무 가깝거나 멀지 않은지)
3. 전신이 화면에 보이는지 확인
4. `pose_detection.py` 로그 확인

### 데이터가 저장되지 않을 때
1. `workout_history.db` 파일 접근 권한 확인
2. 디스크 용량 확인
3. `goal_manager.py`의 DB 연결 확인
